# Termux bridge v0.2 — manual secure receipt relay

This version adds one-time task reservation in SQLite, fixed-format GitHub receipts and automatic issue closure after a task attempt. It **does not** provide unrestricted system-level access, direct MCP connectivity, or autonomous background operation. These require a separately reviewed execution authority design.

## Android install (after PR merge)

Download `worker_v2.py` and `test_worker_v2.py` from a pinned merged commit into `$HOME/termux-github-bridge`. The existing `$HOME/termux-mcp-bridge/bridge.py` and authenticated `gh` CLI are required.

Run `python -m unittest -v test_worker_v2.py`, then `python worker_v2.py` (dry run), then `python worker_v2.py --execute` to process eligible requests.

Only issues authored by `alphatecau`, carrying `termux-bridge-approved`, with exactly `{"schema":1,"tool":"repo_status","repo":"alpha-labs"}` or an allowed repo/tool substitution are accepted. Allowed tools: `repo_status`, `repo_log`; allowed repos: `alpha-labs`, `Q3HASH`.

## Security and limitations

- No raw Git status, commit history, stdout, stderr, file contents or credentials are published to GitHub. Receipts contain task number, tool, repo, status only.
- An issue is reserved in SQLite **before** execution. Interrupted or failed tasks are not retried automatically. A GitHub comment failure leaves a locally recorded task for manual reconciliation.
- This is at-most-once local execution, **not** cryptographically authenticated task submission. Issue authorship and labels can be modified by users with sufficient repository permissions.
- GitHub repository is public. Do not place secrets in issue bodies. Receipts disclose only non-secret task metadata.
- Do not run this with broad filesystem or arbitrary shell permissions. A separate signed task protocol, expiry, replay protection and operator-defined high-risk policies are prerequisites.

# Termux Bridge v0.3 — supervised agent controller

v0.3 adds a restartable foreground polling controller to the tested v0.2 GitHub task relay. It is **not unrestricted remote shell access**. The v0.2 worker continues to restrict execution to repo_status/repo_log on Q3HASH/alpha-labs.

## Start in Android Termux

Install agent_v3.py and test_agent_v3.py from a pinned commit into $HOME/termux-github-bridge beside worker_v2.py. Run:

```sh
cd "$HOME/termux-github-bridge"
python -m unittest -v test_agent_v3.py test_worker_v2.py
python agent_v3.py --once
python agent_v3.py --interval 120 --execute
```

The last command runs until Ctrl+C. Android may suspend Termux in the background; this is not a guaranteed always-on service. Do not use Termux wake locks or battery-exemption settings without reviewing device impact.

## Next security gate before full-system access

Implement an independent task-signing authority that does not expose signing secrets to GitHub issue writers; bind signatures to exact command, parameters, expiry, unique nonce and target device. Add an explicit per-operation risk policy, command argument isolation, output redaction, constrained environment, resource limits, durable idempotency, recovery and independent negative tests. Do not grant arbitrary shell execution to a public-issue label. Full-system access remains disabled.
